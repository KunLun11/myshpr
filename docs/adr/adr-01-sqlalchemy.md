# ADR-01: SQLAlchemy 2.0 async + Alembic

**Status:** Accepted · **Context:** `TASKS.md` §3.

## Decision

Model data with SQLAlchemy 2.0 declarative `Mapped`/`mapped_column`, access DB via
`AsyncSession`, driver `asyncpg`, migrations via Alembic async template.

## Consequences

- Models live in `app/models/*`, base in `app/db/base.py` with a naming convention.
- `app/models/__init__.py` imports everything; `alembic/env.py` passes `Base.metadata`.
- Autogenerated migrations are always reviewed by hand (types, enums, `ondelete`,
  partial indexes, cross-referencing FKs).
- Session factory uses `expire_on_commit=False`; one session per request.
- Relationships are loaded explicitly (`selectinload`/`joinedload`).

## Known pitfalls (handled)

- Enum types created by `sa.Enum` are not dropped with tables → downgrade drops them
  explicitly.
- `use_alter=True` FKs are skipped by `op.create_table` → the initial migration adds
  them with explicit `op.create_foreign_key`.
